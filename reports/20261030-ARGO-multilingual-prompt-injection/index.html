언어별 규칙을 골라 싣는 장치

번역 규칙 파일을 언어별로 두고, 설치가 고정한 언어의 파일만 영어 규칙 뒤에 덧붙여 싣습니다. 한국어와 독일어 규칙도 여기서 함께 들어왔습니다.

왜 바꿨나

  • 모든 언어를 늘 싣지 않고, 한 사용자는 영어 + 자기 언어 하나의 비용만 내게 하려는 것입니다.
  • 두 검사 지점이 한 엔진을 함께 스캔하므로, 언어 목록은 프로세스 전체에 하나여야 하고 엔진을 만든 뒤에 바뀌면 안 됩니다.

ARGO CLI 가 언어를 고르는 방법

ARGO 는 PII 국가와 같은 입력([pii] locales, 없으면 기기 locale)에서 언어를 정해 설치에 넘깁니다. 새 설정 키는 없습니다.

왜 바꿨나

  • 사용자가 한 번 정한 locale 이 PII 국가와 prompt injection 언어를 함께 정하게 해서, 설정 하나로 두 동작이 어긋나지 않게 하려는 것입니다.
  • 영어는 늘 실리므로, 언어를 찾지 못해도 부팅을 멈출 이유가 없습니다.

실제 코드: tinicli/src/cli_entry.rs:429-470 · tinicli/src/guardrails/prompt_injection.rs:83-118
  • 설정값은 PII 가 읽는 방식 그대로 읽습니다. 두 글자는 국가(kr)이고, 그 나라의 주 언어(PiiCountry::language())가 됩니다. 그래서 두 글자 ko 는 언어가 아니라 없는 국가로 읽히며, 그런 값은 PII 쪽에서 이미 부팅을 멈춥니다.
  • 기기 locale 에서는 두 글자가 언어입니다(ko → 한국어). 설정값과 기기 값의 해석이 다른 점에 주의해야 합니다.
  • to_core_config 는 언어를 정하지 않고 빈 languages 만 채웁니다. 언어는 cli_entry 에서 설치 직전에 넣으므로 [prompt_guard] 만 켜고 도구 결과 검사를 꺼도 언어가 적용됩니다.

핵심 포인트

  • [pii] locales 문서 주석에 이 키가 prompt injection 언어도 정한다는 설명이 추가되었습니다.
  • 기존 tinicli 테스트의 호스트 규칙 id ko_ignore_prior 는 이제 예약된 번역 id 이므로 host_ignore_prior 로 바뀌었습니다.
  • 기기 locale 에서 codeset·modifier 를 떼는 코드는 locale_tag 로 빼서 PII 와 함께 씁니다.
