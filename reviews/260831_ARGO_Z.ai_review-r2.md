# PR Review: PII Guardrails / Egress Masking

Overall this is a well-documented, carefully-tested change. A few substantive issues to address:

## High priority

**1. Per-run PII guardrails silently shadow operator-configured global chains (security)**

`guardrails.rs`'s `layer_chain` semantics are *prefer* ("the per-run one when non-empty, else the global one"). But `tinicli` now sets `config.guardrails = pii_input_guardrails.cloned()` (repl.rs, run_tui.rs) whenever `pii_mode != "off"`. If an operator has configured `ARGO_GUARDRAIL_DENY_*` chains via `install_guardrails_from_env`, the per-run PII set **replaces** them for both the admission gate and `agent_loop`'s internal pass — the operator's input rules (and the global set's tool/output layers) are silently skipped. Note the contradiction: `run_input_guardrails_with_text`'s own doc says it "combines" `per_run` with the global set; `layer_chain`'s doc says it prefers. Either make resolution a union, or only attach the PII set as per-run when the global slot is empty.

**2. Audit all `dispatch_stream` consumers for `corrected_content`**

`dispatch_stream` now always opts into unsuppressed deltas (`allow_unsuppressed_masked_deltas = true`), so raw `[SENS:PII:...]` placeholders flow live to every consumer. `argo-wasm` was updated to prefer `Done.corrected_content`; any other in-tree consumer of `dispatch_stream` that concatenates `Text` chunks (or fans them out to a client) will surface unresolved placeholders. Please verify there are no other consumers, or handle the field there too.

## Medium priority

**3. Background-call latency regression with masking installed**

With a global policy installed, *every* background LLM call (compaction, title, sub-agents, judges) now runs the full DFA scan over the entire outbound batch — your own docs measure ~17.5 µs/byte on varied text. A 500 KB compaction context adds ~9 s; 1 MiB ~18 s. This is synchronous on the hot path with no size gate. The docs acknowledge this honestly, but shipping it means real latency regressions for `pii_mode = "full"` users with long histories. Consider at least a metric/log on masked-background-call scan duration, and a follow-up ticket for chunked/parallel scanning.

**4. `argo-server`: PII block surfaces as `GatewayError::Internal`**

A user pasting a card number into gateway chat gets a kernel-level "Internal" error — likely a 500 to the client and possibly on-call alerting, for what is a client-side rejection. Use a dedicated error variant that maps to a 4xx/structured refusal.

**5. Fail-open defaults on a privacy control**

- `PiiMode::parse("fll")` → silent `Off` (a config typo disables protection).
- `build_pii_for_turn` engine-build failure → `(None, None)`, process continues unprotected (error log only).

Both are defensible for embedded/tested config, but for the parse case at least, consider failing startup or emitting a loud operator-visible warning; a typo silently disabling a security control is the kind of gap this PR exists to close elsewhere.

**6. `filter_test.rs` missing from the diff**

`Cargo.toml` declares `[[test]] guardrails_filter_test` and `layer_coverage_guard.rs` does `include_str!("filter_test.rs")`, but the file isn't in this PR. If it was truncated/omitted accidentally, the build breaks — please confirm it's included.

## Minor

- **argo-md `agent.rs`**: the blocked `ChatMessage` reuses the user turn's `id.clone()` — may collide with frontend keying/dedup; consider a distinct id.
- **`PiiSpanDetector::detect`**: `.unwrap_or_default()` on `spawn_blocking` swallows panics as "no spans" — silent fail-open. Add a `tracing::error!` on `JoinError`.
- **`filter.rs`**: `mask()` lost its doc comment — its doc text got attached to `min_cache_info` above it.
- **Doc drift**: AGENTS.md/README describe the bench as covering all three layers via the shared cached compile; `pii_bench.rs` actually cold-compiles via `build_filters_with_params` and benchmarks only the default layer. The ci-linux comment lists "6 `[[test]]` targets" but Cargo.toml declares 7 (missing `guardrails_layer_coverage_guard`).
- **`keyword_files_available`** falls back to CWD-relative filesystem checks (`config/...`, `Path::new(p).exists()`) at *runtime* — behavior becomes CWD-dependent in production. The embedded lookup should be authoritative; drop the disk fallback.
- **`inject_guidance_chat`**: for a multipart System message, `system.text()` + `sanitize_text_content(text)` likely replaces the multi-part content with plain text, dropping other blocks. Guard for non-plain System/User content like the `LlmMessage` counterpart does.
- **Test hygiene**: `install_cred_guardrail` ignores the `install_guardrails` return ("first-install wins"), so tests in `inbound_admission_e2e.rs` can silently run against a different test's chain if execution order changes. The per-run `CountingCredDetector` sets avoid this for the cache tests — consider the same pattern throughout.

## Notes (no action needed)

- The duplicated 55-line `install_guardrails_from_env` match block in argo-md/argo-server is explicitly justified; fine.
- The cross-turn scan cache design (content-addressed + chain-identity with Arc keep-alive against ABA) is sound, and the degraded-pass non-caching guard is a nice touch.
- `MAX_CHAINS = 8` silently disables caching beyond 8 distinct chains — acceptable, just be aware sub-agents building fresh `GuardrailSet`s per run will churn buckets.
